# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## О проекте

**Neurodoc Editor** — редактор каталогов документации в формате **neurodoc** в трёх
версиях: для Windows 11 (C# / .NET 10, WinUI 3 / Windows App SDK, unpackaged + self-contained),
для Linux (Rust, GTK4 / libadwaita, WebKitGTK) и для Android (Kotlin + Compose). Работа с
каталогом устроена как браузер: файлы связаны ссылками, по ним переходят кликом,
редактирование — с автосохранением.

Раскладка репозитория:

- `windows/` — десктопное приложение для Windows (см. также `windows/README.md`);
- `linux/` — десктопное приложение для Linux (см. `linux/README.md`);
- `android/` — мобильное приложение (Kotlin + Compose, см. `android/README.md`);
  **функциональность и пользовательские истории у всех трёх версий одинаковые** — правку
  формата или поведения нужно доводить до всех трёх;
- `README.md` — лицевая страница на GitHub: обзор, краткая спецификация формата, сборка
  (с коротким абзацем на английском для иностранных посетителей);
- `doc/` — документация проекта для людей, сама в формате neurodoc (открывается в редакторе
  как проект). Пересказывает то же, что этот файл, но для читателя, а не для агента:
  **правку поведения нужно доводить и туда**, иначе описания разъедутся;
- `book/` — сайт-книга на mdBook 0.5 (оглавление — `book/src/SUMMARY.md`): формат, работа в
  редакторе, git, сборка и устройство. Её выкладывает на GitHub Pages workflow
  `.github/workflows/pages.yml` при push в `main`. **Правку поведения доводить и сюда.**
  Скриншоты в `book/src/images/` (WebP без потерь) — снимки самопроверки Linux-версии
  (`NEURODOC_SMOKE`) на копии `example/`; пересоздаёт их `./book-shots.sh` — в безэкранном
  `mutter --headless` (у заблокированного экрана снимки пустые), с `TZ=UTC` (время в
  истории git = сообщениям коммитов) и относительным путём проекта (в диалоге «Проекты»
  нет длинного служебного пути; вердикты `smoke: слежение …` в этом прогоне поэтому не в
  счёт — `notify` даёт абсолютные пути). Светлая тема — отдельным запуском: переключение
  на лету безэкранный снимок не ловит. Локально книга собирается `mdbook build book`
  (выход — `book/build/`);
- `example/` — эталонный каталог neurodoc для проверок; **не менять при тестировании**.
  Это выдуманный проект Fikus (сервис ухода за комнатными растениями): домены `*.fikus.example`,
  IP из документационных диапазонов. На его файлы завязаны тесты (`linux/tests/domain.rs`:
  `contract/auth/start.yaml`, `contract/dto/Account.yaml`, ссылка-путь на `contract/dto/Plant.yaml`
  из «Растения — концепция», поиск слова Fikus) и самопроверка (длинные `root` и `README.md`).

UI, комментарии в коде и документация — на русском.

**Репозиторий публичный** (github.com/vabuter/neurodoc, лицензия MIT). В отслеживаемые файлы и
сообщения коммитов не попадает ничего о личных проектах пользователя, его серверах, токенах и
путях к его каталогам; примеры — только на зарезервированных доменах (RFC 2606) и
документационных адресах (RFC 5737, RFC 3849).

## Формат neurodoc (доменная модель)

- Каталог = корневой файл `root` + папка `_content/`, имена файлов в ней — UUID в нижнем
  регистре. Подчёркивание помечает папку служебной, но, в отличие от точки, не прячет её:
  каталог смотрят и файловым менеджером, и с телефона. Обычное `content/` оставлено
  свободным под прикладную папку самого проекта. Единственное место, где имя записано, —
  `NeurodocCatalog.ContentDir`.
  **`_content` не начинается с точки, поэтому обход каталога отбрасывает её отдельной
  проверкой по имени** (`EnumerateDomainFiles` / `enumerateDomainFiles`): без этого файлы-UUID
  попали бы в каталог второй раз — как файлы в собственном формате с путём `_content/<uuid>`.
- Все файлы в UTF-8 **без BOM**.
- Переводы строк при сохранении не меняются: RichEdit отдаёт текст только с CRLF, поэтому перед
  записью он приводится к стилю исходного файла (в существующих каталогах — LF).
- Ссылка — `[текст](uuid)`: `[подход к разработке](5c673c53-8ad9-49eb-9fb6-ffb3954848f0)`. Текст
  ссылки (якорь) встроен в предложение, однострочный и не содержит `]`; пустой якорь `[](uuid)`
  означает «показать заголовок целевого файла». Голый UUID ссылкой не считается, как и `<uuid>` —
  это прежняя форма, её переводит `Services/CatalogMigration.cs` (с резервной копией каталога в
  `%APPDATA%\NeurodocEditor\backups`), предлагая миграцию при открытии проекта.
- Кроме `_content/` в каталоге бывают папки с файлами в собственных форматах (YAML, SVG,
  конфиги) — имена у них доменные, читают их и программы. В ссылке вместо UUID может стоять
  **путь к такому файлу относительно того файла, где написана ссылка**:
  `[auth.start](../contract/auth/start.yaml)` из файла в `_content/`. Отсюда главное следствие:
  **цель ссылки неполна без источника** — разбирает её `NeurodocCatalog.TryResolveLink(sourceId, …)`,
  а `GetLinks(id)` отдаёт уже разрешённые. Подстрокой обратные ссылки больше не найти: один файл
  адресуется из разных папок разными путями.
- Ссылок наружу каталога не бывает. `TryResolveLink` отвергает подъём выше корня, абсолютные пути
  и диски, `IsValidId` страхует сверху, а `GetFilePath` на негодном id **бросает исключение**:
  молчаливая подмена на `root` приводила к тому, что `Exists` отвечал «файл есть», а запись ушла бы
  в `root`. Отвергнутая ссылка не рисуется чипом и попадает в «Битые ссылки».
- **Источники ссылок — только neurodoc-файлы** (`root` и `_content/`), см. `LinkSourceIds()`.
  Файлы в собственных форматах — цели, а не источники: последовательность `[текст](что-то)`
  встречается в них сама по себе. На этом попался `ReadMe.md` — примеры из описания формата
  приложение считало настоящими ссылками и показывало битыми.
- Идентификатор файла: `root`, UUID из `_content/` либо путь вроде `contract/auth/start.yaml`.
  У пути регистр — часть имени, поэтому к нижнему регистру приводятся **только** UUID.
- Файлы образуют граф знаний с корнем в `root`.

## Команды

Сборка и деплой (bat-файлы в корне репозитория):

```bash
./build-debug.bat      # Debug x64
./build-release.bat    # Release x64
./build-deploy.bat     # Release + self-contained publish в C:\d\deployments\neurodoc_editor
./release.bat 0.2.0    # тег vX.Y.Z на текущем коммите main (без push)
```

**Разработка идёт и на Linux.** У bat-файлов, имеющих там смысл, есть sh-двойники:
`release.sh`, `android-build.sh`, `android-install.sh`. Они повторяют bat-файлы по проверкам
и сообщениям — правку одного доводить до другого; в отличие от `android-*.bat`, при ошибке
не ждут нажатия клавиши. **Windows-версию на Linux не собрать и не запустить**: компилятор XAML и
Windows App SDK работают только под Windows, поэтому у `build-*.bat` двойников нет — C#-код
здесь можно править, а собирать и проверять его — на Windows.

Linux-версия (из корня репозитория; нужны `rust cargo gtk4-devel libadwaita-devel
webkitgtk6.0-devel`, на Fedora — `sudo dnf install …`):

```bash
./linux-build.sh       # cargo build --release → linux/target/release/neurodoc-editor
./linux-run.sh         # сборка и запуск; XDG_CONFIG_HOME=/tmp/x — изолированный экземпляр
./linux-deploy.sh      # release + установка в ~/.local: ~/.local/opt/neurodoc-editor, ссылка в bin, .desktop, иконки
```

**Вручную установленный софт — в `~/.local/opt/<имя>/`** (скрытая папка, по подпапке на
программу), в `~/.local/bin` лежат только ссылки на исполняемые файлы, ярлыки и иконки — в
`~/.local/share/{applications,icons}` (так требует XDG). Так устроены Android SDK
(`~/.local/opt/android-sdk`, ссылка `adb`, `ANDROID_HOME` в `~/.config/environment.d/`) и сама
Linux-версия. Кэши инструментов (`~/.gradle`, `~/.cargo`, `~/.android`) не трогаем.

Проверка Linux-версии: `cargo test` в `linux/` (домен и git на копии `example/` во временной
папке) и самопроверка интерфейса `NEURODOC_SMOKE=/папка ./linux/target/debug/neurodoc-editor`
— приложение само проходит по файлам, режимам и диалогам и кладёт снимки окна в папку,
а в конце пишет в stderr строки `smoke: прокрутка …`, `smoke: курсор …` и `smoke: слежение …`
(то, чего не видно на снимке: не сбрасывается ли прокрутка редактора и просмотра, «рука» ли
над ссылкой, не перечитывается ли каталог от своего автосохранения и подхватывается ли чужая
правка сразу после него, в том числе в открытом файле с точкой — шаг слежения сам правит `root`
и `README.md` копии и возвращает их, а временный `.smoke-watch.yml` удаляет;
для прокрутки эти файлы должны быть длиннее окна);
`NEURODOC_SNAPSHOT=/путь.png` снимает окно один раз. Настоящие проекты при проверках не
трогать: запускать с `XDG_CONFIG_HOME` на временную папку и копией `example/`.

Вручную (из `windows/`):

```bash
dotnet build NeurodocEditor/NeurodocEditor.csproj -c Debug -p:Platform=x64
```

Запуск после Debug-сборки:

```bash
./windows/NeurodocEditor/bin/x64/Debug/net10.0-windows10.0.22621.0/win-x64/NeurodocEditor.exe
```

**Платформу указывать явно.** Без `-p:Platform=x64` проект получает AnyCPU, и
`WindowsAppSDKSelfContained` падает с «requires a supported Windows architecture». Сборка через
`.slnx` работает благодаря явному маппингу платформ в файле решения; сборка csproj напрямую —
только с `-p:Platform`.

**Версия приложения — только git-тег `vX.Y.Z` на коммите в `main`.** Все три сборки читают его
через `git describe`: Windows — таргетом `SetVersionFromGit` в csproj, Linux — скриптом
`linux/build.rs` (в `Cargo.toml` поля `version` нет намеренно), Android — функцией `git()` в
`app/build.gradle.kts`. Хардкодить номер в csproj, `Cargo.toml`, `build.gradle.kts` или в коде
нельзя — платформы разъедутся, а именно от этого версионирование и заводилось. Показывают её
`AppVersion.Display` и `neurodoc_editor::VERSION` (строка заголовка окна на Windows и Linux)
и `BuildConfig.VERSION_NAME` (диалог настроек на Android). Отступление от правила «UI
одинаковый» здесь сознательное: верхняя панель на телефоне занята именем проекта.
Числовые атрибуты (`AssemblyVersion`, `FileVersion`) SDK формирует **на этапе вычисления
проекта**, когда git ещё не опрошен, поэтому таргет обязан считать в собственные свойства
(`_AppVersionNumeric`), а не полагаться на `Condition="'$(VersionPrefix)' == ''"`: SDK уже
задал там `1.0.0`, и откат не сработает никогда.

У Windows- и Android-версий автотестов нет, у Linux-версии — `cargo test` на домен. Проверка
изменений — запуском приложения; при правках UI имеет смысл снять скриншот окна и убедиться
в результате глазами. Настройки приложения (в т.ч. текущий проект) лежат в
`%APPDATA%\NeurodocEditor\settings.yaml` (Windows) и `~/.config/neurodoc-editor/settings.json`
(Linux), необработанные исключения — в `error.log` рядом (на Linux —
`~/.local/state/neurodoc-editor/error.log`).

## Архитектура

### Слои

- `Services/NeurodocCatalog.cs` — ядро домена. Держит весь каталог в памяти (`id -> контент`) и даёт
  граф-операции: `BuildGraph`, `GetBacklinks`, `GetOrphanFiles`, `FindShortestPathsFromRoot`
  (обход в ширину, затем перечисление путей ровно минимальной длины — **не** обход в глубину
  с отсечкой: тот набирал лимит длинными путями и до короткого не доходил, вместо длины 3
  показывалась длина 5), `Search`, `RemoveLinksTo`, `EnsureStructure` (создание
  `root` + `_content/` + `ReadMe.md`). Любая запись — через `WriteFile` (UTF-8 без BOM + обновление
  кэша в памяти).
  **Разобранные ссылки кэшируются пофайлово** (`ParsedLinks` → `_links`): панели (пути, обратные
  ссылки, сироты, битые, порядок чтения) перестраиваются после каждого автосохранения, и без кэша
  это было пять полных прогонов регулярки по всему каталогу на одну правку. Разбор зависит только
  от текста файла и его папки, поэтому `WriteFile`/`DeleteFile` сбрасывают запись **одного** id,
  а `Reload` — весь кэш. **Любая новая мутация `_files` обязана сбросить и `_links`.**
  Дерево каталога обходится вручную (`EnumerateDomainFiles`), а не через `SearchOption.AllDirectories`:
  тот сначала спускается в `.git` и перечисляет всё, что там лежит, и лишь потом имена
  отбрасываются по маске.
- `Services/SettingsService.cs` — YAML-настройки (YamlDotNet) в `%APPDATA%\NeurodocEditor`.
- `Services/BundledFonts.cs` + `App.xaml.cs` — встроенные шрифты.
- `Services/GitService.cs` — git-операции через системный git.exe (см. «Git-интеграция»).
- `MainWindow` — разбит на четыре partial-файла: `MainWindow.xaml.cs` (навигация, редактор, оверлей
  ссылок, панели), `MainWindow.Find.cs` (поиск по файлу, поиск-и-замена), `MainWindow.Viewer.cs`
  (просмотр форматов и дельт), `MainWindow.Git.cs` (git: меню, конфликты, история). Диалоги — в `Dialogs/`.

### Редактор, оверлей ссылок и прокрутка (самое неочевидное)

Редактор — `RichEditBox` в plain-text-режиме. Ссылки (`<uuid>` и `http(s)://…`) ищутся регулярками,
их прямоугольники берутся из `ITextRange.GetRect`, и поверх текста рисуются интерактивные «чипы»
(`Controls/ChipView` на `Controls/HandCanvas`). Документ форматируется **только** ради компактных
ссылок (п. 4); во всём остальном он не форматируется — иначе засоряется история Undo.

Отсюда пять связанных ограничений, которые нужно держать в голове при любой правке этой области:

0. **`BringIntoViewRequested` у редактора подавляется.** Редактор занимает всю прокручиваемую
   область, поэтому «подтянуть его в видимую область» — это всегда прокрутка к его верху.
   XAML делает это сам, когда редактор получает фокус, причём асинхронно — уже после того, как
   мы вернули запомненную прокрутку, отчего экран прыгал в начало файла. Видимость каретки
   держим только вручную (`EnsureCaretVisible`).
1. **Координаты TOM — контентные и не знают о прокрутке.** Узнать скролл-позицию RichEdit
   невозможно, внутри него нет XAML-элементов прокрутки. Поэтому редактор растёт по высоте контента
   внутри внешнего `ScrollViewer` (`EditorScroll`), а чипы лежат в том же прокручиваемом контейнере
   и едут вместе с текстом. Видимость каретки поддерживается вручную:
   `SelectionChanged` → `EnsureCaretVisible()`.
2. **`GetRect` возвращает координаты без `Padding` контрола** — при отрисовке добавляется
   `Editor.Padding.Left/Top`.
3. **Перерисовку просит `InvalidateOverlay`, и она ровно одна на правку.** Правка внутри строки
   не меняет высоту контента, и `LayoutUpdated` может не сработать вовсе — чипы «зависли» бы на
   старых местах. Но рисовать и сразу, и ещё раз после layout (как было раньше) — это две полные
   перерисовки на каждое нажатие клавиши. Поэтому `TextChanged` только поднимает `_overlayDirty`
   и ставит отложенный вызов: если layout уже прошёл и оверлей перерисован, тот ничего не делает.
   Порядок безразличен — координаты TOM не ждут раскладки XAML.
   Чипы пересоздаются на каждой перерисовке, поэтому кисти (`ChipBrush`) и курсор-«рука»
   (`ChipView.HandCursor`) общие, а наведение перекрашивает только два затронутых чипа, а не все.
3a. **`GetRect` на многострочном диапазоне отдаёт общую обрамляющую рамку.** Если якорь перенесён
   на другую строку, это огромный блок поверх чужого текста. Поэтому `LineRects` разбирает такой
   диапазон посимвольно и группирует по строке — по чипу на строку. Быстрый путь: пока высота
   диапазона в пределах одной строки, посимвольный разбор не запускается.
4. **Компактные ссылки** — обычный вид ссылки; отдельной настройки нет, развёрнутый вид даёт
   тумблер «Как есть» (п. 4a).
   Из `[текст](uuid)` через `CharacterFormat.Hidden` прячутся `]`, `(` и UUID
   (`ApplyCompactLinks`). **Крайние символы ссылки — `[` и `)` — обязаны остаться видимыми**: текст,
   набранный вплотную к ним (в начале якоря или сразу после ссылки), наследует формат соседнего
   символа и от скрытого стал бы невидимым, причём перепроверка этого не заметит — набор ссылок
   ведь не изменился. Поэтому их закрашивают заплатки цветом фона редактора (`ChipKind.Cover`,
   цвет берётся из `EditorCard.Background`, а не константой — иначе разъедется с темой), и глазу
   остаётся только текст якоря с подчёркиванием (`ChipKind.Pill`: прозрачный фон плюс нижняя
   граница). Заливку не используем — при переносе строки якорь разрывается, и фон смотрелся бы
   рвано. Фон именно **прозрачный, а не `null`**: с `null` чип перестанет ловить клики.
   Подчёркивание рисуется **строго по диапазону якоря** (`link.Start + 1 .. AnchorEnd`) и без
   полей по бокам: захватив закрашенные `[` и `)`, черта торчит и читается как лишние пробелы.
   Кликабельность от этого не страдает — заплатки тоже лежат в `_chips` с тем же индексом ссылки.
   Ссылка без якоря целиком уходит под непрозрачный кружок (`ChipKind.Solid`); рядом с якорным
   текстом такой значок был бы избыточен.
   Непрозрачность заплаток и кружка обязана быть **полной**: при альфе 0xD8 служебные символы
   просвечивали сквозь заливку.
   Формат применяется только при изменении набора ссылок, а подпись набора берётся из целей
   **без позиций** — при вставке текста перед ссылкой RichEdit двигает формат вместе с символами
   сам, и позиции в подписи заставляли бы переформатировать документ на каждой правке.
4a. **Режим «как есть»** (`AppSettings.RawEditing`, тумблер «Как есть» слева от кнопок форматов).
   Файл показывается ровно как на диске: ничего не скрывается, оверлей ссылок не рисуется
   (совпадения поиска остаются — без них найденное не видно). Нужен, чтобы править текст
   посимвольно. Скрытие при включении снимается **явно** (`ClearHiddenFormatting`): само
   `ApplyCompactLinks` этого не сделает — в режиме «как есть» подпись набора ссылок равна
   `null`, совпадает с сохранённой, и ветка снятия скрытия не выполняется.
5. **RichEdit кладёт форматирование в тот же стек Undo, что и правки текста.** Поэтому
   Ctrl+Z / Ctrl+Shift+Z перехватываются (`UndoSkippingFormatting`) и пропускают шаги, не изменившие
   текст, — иначе первый Ctrl+Z просто разворачивал бы ссылку. И отдельно: стек Undo принадлежит
   контролу, а не документу, и переживает `SetText`, поэтому при каждой загрузке файла он сбрасывается
   (`ClearUndoHistory`). Без сброса Ctrl+Z в только что открытом файле затягивал в него текст
   предыдущего, а автосохранение записывало это на диск (проверено — так терялось содержимое `root`).

Правки на диске подхватываются сами: `FileSystemWatcher` на корне проекта, пачка событий
гасится таймером на 500 мс, дальше `ReloadFromDisk`. Собственную запись отличаем **по
содержимому** (`NeurodocCatalog.MatchesDisk` / `matches_disk`): событие пропускается, только
если для всех его путей файл на диске совпадает с текстом в памяти каталога (или его нет ни
там, ни там) — иначе каждое автосохранение вызывало бы перечитывание. **Не по времени**: прежняя
проверка «приложение писало меньше секунды назад» глотала любое событие в эту секунду, и чужая
правка сразу после автосохранения (git pull в терминале, другая программа) терялась — в памяти
оставался старый текст, и следующее автосохранение записывало его поверх. Сомнение решается в
пользу перечитывания: папки, незнакомые файлы, пути вне каталога, переполнение очереди событий
(`InternalBufferOverflowException` в `Error` у `FileSystemWatcher`, `need_rescan` у `notify`),
удалённое под коротким именем 8.3. Прочие ошибки `FileSystemWatcher` (отвалился сетевой или
съёмный диск) каталог **не** перечитывают: недоступный, он прочёлся бы пустым и опустошил редактор.
Правила, проверенные ревизией:
- **файл, который каталог держит в памяти, сверяется всегда** — и с точкой в пути, и больше
  4 МБ: такие перечитывание не заводит, но в память их кладёт запись (правка файла, открытого по
  ссылке вроде `.gitlab-ci.yml`). Пропускаются без сверки только **незнакомые** файлы, которые
  перечитывание и так отбросит: с точкой в пути, больше 4 МБ, двоичные;
- **открытый файл сверяется ещё и с `_lastSavedText`** (`CurrentFileChanged` / та же проверка в
  `on_catalog_changed_on_disk`): каталог может его и не держать — файл с точкой или большой
  читается с диска мимо памяти, а `ReloadFromDisk` сверяет его именно с последним сохранённым;
- **двоичность — по нулю в первых 8 КБ** (`StartsBinary` / `starts_binary`), не по всему файлу:
  генераторы картинок пишут кусками, событий сотни, и полное чтение до 4 МБ на каждое вешало
  поток интерфейса (замер: 9 с на PNG в 3 МБ). Нуль в начале — точно двоичный; без него ответ
  «изменился», и дальше разбирается одно перечитывание. На Windows начало декодируется тем же
  способом, что `File.ReadAllText` (с BOM): текст в UTF-16 содержит нулевые байты, а не символы;
- **написание сверяется**: на Linux ФС различает регистр (`e.id == id`), на Windows — нет, и
  переименование `Start.yaml` → `start.yaml` видно только по написанию в событии;
- у `FileSystemWatcher` в `NotifyFilter` есть `DirectoryName`: без него перенос или удаление папки
  целиком не давали ни одного события.

Пока перечитывание уже назначено, события его только отодвигают и не сверяются. Файл в
редакторе перезагружается, только если своих несохранённых правок нет; вручную — кнопка
«Обновить» или F5.

### Просмотр форматов

**«Как есть» — такой же режим показа, как SVG или MD, а не независимый тумблер.**
Включение «как есть» выходит из отрисованного формата, выбор формата снимает «как есть»
(`OnRawToggle` ↔ `SetViewModeAsync`; на Android `setRawEditing` ↔ `changeViewMode`).
Кнопка MD стоит сразу после «Как есть»: из отрисовываемых форматов он нужен чаще прочих.

**SVG показывается с масштабированием**: колесо/щипок, перетаскивание, двойной щелчок и
кнопки `+ − ⟲ ☀/☽` в углу. Скрипт один и тот же в `MainWindow.Viewer.cs`, `FormatViewer.kt`
и `linux/src/viewer/scripts.rs` — расходиться им нельзя. Скрипт ссылок `ViewerLinkScript`
побайтно одинаков на Windows и Linux, а на Android отличается только последней строкой —
вызовом моста (`NeurodocHost.openLink`). Хост на Linux скрипты не меняет: пользовательский
скрипт WebKit подставляет `window.chrome.webview.postMessage`, и страница думает, что она
в WebView2. У BPMN-рисунков нет собственных размеров, только `viewBox`, и в
абсолютно спозиционированном контейнере они схлопываются в ноль, поэтому перед подгонкой
скрипт проставляет `width`/`height` из `viewBox`.

**Фон просмотра рисунков — настройка проекта, а не приложения** (`ProjectInfo.SvgBackground`
/ `svgBackground`: "Light" | "Dark" | null). Пока пользователь не трогал кнопку ☀/☽, там null
и работает тема; первое переключение запоминается и дальше побеждает тему. Рисунки одного
проекта нарисованы под один фон, поэтому настройка именно проектная. Обе палитры уходят
на страницу CSS-переменными (`html.dark`), так что кнопка меняет фон без перезагрузки, а
о выборе сообщает хосту: на Windows — `postMessage("svgbg:…")`, на Android — метод моста
`NeurodocHost.setSvgBackground`.

**MD и AsciiDoc рендерятся шрифтом из настроек редактора** — семейством, размером и
интервалом: отрисованный документ должен читаться так же, как текст, из которого он собран.
Встроенный шрифт вкладывается в страницу через `@font-face` с data-URI (WebView2 и WebView
не видят его по имени: в WinUI он ставится для пользователя ради другого текстового стека,
а в Android лежит в `res/font`). Файл весит сотни килобайт и читается один раз, дальше
живёт в кэше. Код в документе остаётся моноширинным при любом выборе.

Файл в собственном формате открывается **сразу отрендеренным**: `OpenFile` определяет режим по
расширению (`DetectViewMode`) и включает его. Так эти файлы и читают, а чтобы править, режим надо
осознанно выключить — контракты труднее задеть случайно. У `root` и файлов `_content/` расширения
нет, для них режим остаётся текстовым.

**Расширение решает только при первом заходе.** Выбранный режим лежит в `ViewState` рядом с
кареткой и прокруткой и при возврате в файл побеждает расширение: выключенный рендер у `.md`
не включается заново (пользователь ушёл править текст), а включённый вручную MD у файла без
расширения — восстанавливается. Состояние живёт до смены проекта, как и остальной `ViewState`.

Прогресс чтения считается только по neurodoc-файлам: контракты — справочные данные, их читают по
необходимости, а не подряд, поэтому в обход они не входят и тумблер «Прочитано» для них выключен.
**Кнопка «Далее» выключена, пока текущий файл не отмечен прочитанным**: это шаг вперёд по
порядку чтения, а уходить из неотмеченного файла значит оставлять дырку, к которой придётся
возвращаться. Файлы в собственных форматах ничего не задерживают — они вне обхода.

`MainWindow.Viewer.cs` — кнопки SVG / JSON / YAML / Bash / MD / AsciiDoc / HTML над редактором.
Рендер идёт в `WebView2` через `NavigateToString`, библиотеки (`highlight.js`, `marked.js`,
`asciidoctor.js`) лежат в `Assets/Highlight` и **встраиваются в HTML инлайном** — офлайн, без CDN.
JSON дополнительно форматируется через `System.Text.Json` (нужен `UnsafeRelaxedJsonEscaping`,
иначе кириллица экранируется). Окружение WebView2 создаётся через
`CoreWebView2Environment.CreateWithOptionsAsync` (перегрузки `CreateAsync` с двумя аргументами в
WinRT-проекции нет).

**Ссылки в отрендеренных MD и AsciiDoc кликабельны** (`ViewerLinkScript` + `OnViewerLinkClicked`):
скрипт гасит переход самого WebView2 (иначе он ушёл бы с отрисованной страницы) и шлёт цель хосту
через `postMessage`, а хост разбирает её относительно **текущего** файла и открывает, как обычную
ссылку. Markdown делает из `[текст](цель)` тег `a` сам, а **AsciiDoc такого синтаксиса не знает** и
оставляет его текстом — поэтому скрипт дополнительно размечает такие места сам, обходя текстовые
узлы и не трогая содержимое `a`, `code` и `pre`. Несуществующая цель никуда не ведёт: в `ReadMe.md`
ссылки из описания формата указывают на файлы-примеры, которых в каталоге нет.

### Git-интеграция

Весь рабочий цикл git встроен во все три приложения (истории: публикация, клонирование,
ветки, «Сохранить/Получить/Синхронизировать», история, дельты). Ядро — тройка сервисов,
повторяющих друг друга файл в файл по смыслу: `Services/GitService.cs` (обёртка над
системным git.exe), `linux/src/domain/git.rs` (обёртка над системным git, блокирующие
вызовы в фоновом потоке) и `data/GitService.kt` (встроенный JGit — системного git на
Android нет). UI: `MainWindow.Git.cs` + карточка истории в правой панели (Windows),
`linux/src/ui/window/git.rs` (Linux, та же карточка), `ui/GitDialogs.kt` + панель истории
и `GitDiffViewer` (Android). На Linux учётные данные для HTTPS берутся из credential helper
git (`libsecret`), а проще работать по SSH: `GIT_TERMINAL_PROMPT=0` запрос пароля не пустит.

Принципы, зафиксированные пользователем:
- **каждый commit сразу push** — отдельной операции commit в UI нет; сообщение
  шаблонное: `yyyy-MM-dd HH:mm · <устройство>`;
- конфликты не сливаются: операция откатывается, пользователь выбирает — взять
  серверные (`fetch` + `reset --hard origin/<ветка>` + `clean -fd`), взять свои
  (`push --force`, именно `--force`: `--force-with-lease` без свежего fetch отказывает
  и ломает семантику «затереть») или отменить; **резервных копий не делается**;
- «Синхронизировать» = commit → `pull --rebase --autostash` → push; отказ rebase
  определяется по наличию `.git/rebase-merge|rebase-apply` (не по тексту ошибки),
  затем `rebase --abort` и единый трёхкнопочный диалог;
- переключение веток прячет правки в stash с меткой `neurodoc-auto:<ветка>` и
  возвращает их при переходе обратно. **Git приписывает к сообщению stash-записи
  «On <ветка>: »** — искать нужно хвост subject после этой приписки, сверяя метку
  целиком (проверено: без отрезания приписки stash не находился и правки
  не возвращались);
- default-ветка: `symbolic-ref refs/remotes/origin/HEAD`, при неудаче — одна попытка
  `remote set-head origin --auto`, дальше main/master/первая локальная.

git.exe запускается с `-c core.quotepath=off` (иначе кириллические имена файлов —
октальные последовательности) и `GIT_TERMINAL_PROMPT=0` (без кредов — ошибка, а не
зависание в невидимой консоли); оба потока процесса дочитываются **до**
`WaitForExitAsync`, иначе дедлок на заполненном пайпе. `IsGitAvailableAsync`
кэшируется; публикация выставляет `core.autocrlf false` локально в репозитории.

FileSystemWatcher при git-операциях: события из `.git` отбрасываются по имени,
на время операции (`_gitBusy`) слежение молчит — каталог перечитывается явно по её
окончании (`RunGitAsync` → `ReloadFromDisk` → `EnsureCurrentFileExists`: текущий файл
мог исчезнуть после pull/reset — открывается root). `InternalBufferSize` поднят до
64 КБ: большой checkout переполняет дефолтные 8 КБ.

JGit на Android: перед первым обращением задаётся `user.home` (на Android он пуст —
JGit падает в FS_POSIX); `add` двухпроходный (`addFilepattern(".")` плюс тот же с
`setUpdate(true)` — иначе не стейджатся удаления); identity автора — из настроек
приложения (`gitUserName`/`gitUserEmail`, глобального git config на телефоне нет),
всегда явным `PersonIdent`; у JGit нет `push -u` — upstream прописывается в
`StoredConfig` руками. Токены — по хостам (`gitAccounts`, username по умолчанию
`oauth2` для gitlab.com), хранятся в settings.json, который исключён из облачного
бэкапа (`backup_rules.xml`). Все операции — `withContext(Dispatchers.IO)`: сеть в
main-потоке Android запрещена. В gradle: `slf4j-nop` (глушит warning JGit) и
расширенные `packaging.excludes` (`META-INF/DEPENDENCIES` и пр.; `META-INF/services`
не исключать — там транспорты JGit).

HTML дельты (`BuildDiffHtml` в `MainWindow.Viewer.cs`, `build_diff_html` в
`linux/src/viewer/html.rs` и `buildDiffHtml` в `GitDialogs.kt`) — один и тот же вид,
расходиться им нельзя. На Windows дельта — не
режим формата и не попадает в `ViewState`: флаг `_diffActive` сбрасывается в
`ResetViewMode` **до** раннего выхода (дельта показывается при текстовом режиме,
ранний выход её бы не снял).

Проверка — локальным bare-репозиторием, без сети и токенов: `git init --bare` и URL
вида `file:///C:/путь/х.git` (Windows) или `file:///sdcard/…` (Android; bare заливать
не через `adb push` целиком — он теряет пустые папки `objects/` и `refs/`, их надо
досоздавать `mkdir`). Тестовый каталог — копия `example/` во временной папке.

### Ресурсы и шрифты

Implicit-правила WASDK **не копируют** `Assets/**` в выходную папку — это делают кастомные таргеты
`CopyAppAssets` / `CopyAppAssetsOnPublish` в csproj. Inter и JetBrains Mono при первом запуске
устанавливаются для текущего пользователя (копия в `%LOCALAPPDATA%\Microsoft\Windows\Fonts` +
запись в HKCU): текстовый стек Windows App SDK не видит шрифты, подключённые иначе. Для встроенных
шрифтов имя семейства **не** задаётся в формате документа RichEdit — иначе он откатывается на
шрифт по умолчанию; применяется только `FontFamily` контрола.

## Android-версия

Порт того же домена (как и `linux/src/domain/catalog.rs`): `data/NeurodocCatalog.kt`
повторяет `Services/NeurodocCatalog.cs` файл в файл по смыслу — те же `tryResolveLink`,
кэш разобранных ссылок, обход в ширину для кратчайших путей, порядок чтения, обход каталога
без захода в папки с точки. Расхождение в любом из них — ошибка, а не «особенность
платформы».

Сборка и установка: `android-build.bat` / `android-install.bat` из корня, на Linux —
`android-build.sh` / `android-install.sh`.
**В автоматизации на Windows зовите `android/gradlew.bat assembleDebug` напрямую**: bat-файлы
при ошибке выполняют `pause` и ждут нажатия клавиши — процесс висит до таймаута. sh-скрипты
так не делают, их можно звать как есть.

SDK Gradle ищет в `android/local.properties` (его пишет Android Studio, в git он не попадает),
затем в `ANDROID_HOME` / `ANDROID_SDK_ROOT`. Если не задано ничего из этого, sh-скрипты
подставляют `~/.local/opt/android-sdk` — туда SDK и установлен (см. «Вручную установленный софт»;
Android Studio при установке указать тот же путь).

**Debug-APK подписан ключом той машины, где собран** (`~/.android/debug.keystore`). Поверх
приложения, собранного на другой машине, он не встанет (`INSTALL_FAILED_UPDATE_INCOMPATIBLE`):
либо перенести ключ, либо удалить приложение — а с ним и `settings.json` с git-токенами.

Отличия, которые пришлось учесть:

- **Словари каталога — регистронезависимые** (`TreeMap(String.CASE_INSENSITIVE_ORDER)`),
  как `StringComparer.OrdinalIgnoreCase` в C#. Иначе «ReadMe.md» не находит «README.md»,
  и тот же файл под другим написанием выглядит как чужой — без заголовка и обратных ссылок.
  Ключ при этом хранится как на диске: у пути регистр — часть имени.
- **Компактные ссылки делает `VisualTransformation`**, а не скрытие символов: служебная
  часть просто не попадает в показываемый текст, а `CollapseOffsetMapping` пересчитывает
  позиции каретки и тапов. Проще, чем оверлей в WinUI, и вся возня с чипами не нужна.
- **Долгое нажатие на ссылке открывает файл, а не выделяет текст**: обработчик указателя
  забирает событие себе. Чтобы выделить текст, нажимайте вне ссылки.
- **Действия из меню обязаны брать последнее непустое выделение, а не текущее.**
  Открытие меню уводит фокус из поля, и Compose схлопывает выделение — «Связать» видел
  пустой диапазон и отказывался. В Windows-версии для этого есть `_lastSelection`
  («фокус мог уйти на кнопку»); на Android — `actionSelection()` с тем же смыслом.
- **В режиме «как есть» тап по ссылке не перехватывается совсем.** Иначе внутрь ссылки
  нельзя поставить курсор, а править её вручную — единственное, ради чего этот режим есть.
  Windows ведёт себя так же: там в этом режиме оверлей со ссылками не рисуется.
- **Тап проверяется по прямоугольникам глифов ссылки (`lineRects`), а не по позиции
  символа.** `getOffsetForPosition` возвращает БЛИЖАЙШИЙ символ, даже когда палец далеко
  за концом строки, — от этого пустое место справа от ссылки открывало файл, будто ссылка
  занимает всю строку (пользователь это поймал). Проверять надо попадание точки в
  прямоугольник, и построчно: перенесённый якорь иначе накроет общей рамкой чужой текст.
- **Переход по ссылке из отрендеренного MD/AsciiDoc** идёт через `addJavascriptInterface`
  (`window.NeurodocHost.openLink`). JS-интерфейс вызывается не в UI-потоке, поэтому
  переход отправляется в главный поток через `Handler(Looper.getMainLooper())`.
- **Прокрутку при возврате «назад» восстанавливаем не сразу**: пока раскладка не досчитана,
  `scrollState.maxValue` равен нулю и `scrollTo` уводит в начало файла. Ждём ненулевого
  `maxValue` (та же грабля, что и в WinUI, только лечится иначе).
- **Проверять только на тестовом каталоге.** Настоящие каталоги пользователя на телефоне
  (в `/storage/emulated/0/Projects/`) не трогать. Тестовый каталог
  кладут в `/sdcard/Develop/neurodoc_example`, проект переключают подменой
  `files/settings.json` через `adb shell run-as`, а после проверки возвращают обратно.

## Linux-версия

Rust (edition 2024), gtk4-rs 0.11 / libadwaita 0.9 / webkit6 0.6. **Нижняя планка — GTK 4.14 и
libadwaita 1.5** (Ubuntu 24.04, Debian 13, Fedora 40+): фичи крейтов `v4_14` / `v1_5` не дают
скомпилировать API новее, цвета заданы через `@define-color`, а не CSS-переменными. Планка
касается системных библиотек; компилятор нужен свежий — rustc ≥ 1.92 (на старых
дистрибутивах — через rustup). Акцент — teal из иконки, как на Android. `linux/src`:

- `domain/` — порт того же домена, что и на Android: `catalog.rs` повторяет
  `Services/NeurodocCatalog.cs` файл в файл по смыслу, `git.rs` — `GitService.cs`,
  `settings.rs` / `reading.rs` — JSON в формате Android (`~/.config/neurodoc-editor/`).
  Позиции в тексте здесь **байтовые** (UTF-8), а не UTF-16, как в C#: так их понимает
  GtkTextBuffer (`iter_at_line_index`). Запись файла идёт по тому написанию id, под которым
  он уже известен каталогу: файловая система Linux различает регистр, и ссылка `readme.md`
  на `ReadMe.md` иначе создала бы второй файл.
- `viewer/` — `html.rs` строит те же страницы, что `BuildViewerHtml`; библиотеки и шрифты
  вкладываются в бинарник `include_str!/include_bytes!` прямо из
  `windows/NeurodocEditor/Assets` — третьей копии ресурсов нет.
- `ui/editor/` — редактор на `GtkTextView` с тегами, `ui/window/` — окно, разбитое по
  образцу partial-файлов Windows (`mod.rs`, `panels.rs`, `links.rs`, `find.rs`, `viewer.rs`,
  `git.rs`, `dialogs.rs`, `shortcuts.rs`).

Компактные ссылки делают **теги `GtkTextView`**, а не оверлей (как в WinUI) и не
преобразование текста (как на Android): `(цель)` скрыта тегом `invisible`, `[` и `]`
остаются в раскладке, но красятся цветом фона редактора (прозрачный `foreground-rgba`
GTK рисует серым), якорь подчёркнут. Отсюда правила, проверенные спайком и самопроверкой:

- **Каретка не должна стоять перед скрытым текстом и внутри него.** GTK даёт остановку между
  `]` и невидимой `(`; набранное там порвало бы ссылку, а внутри цели — унаследовало бы
  невидимость. Страж в `mark-set` переносит каретку за ссылку **синхронно**: отложенный
  перенос проиграл бы быстрому набору. В итоге у ссылки ровно четыре остановки: перед `[`,
  начало якоря, конец якоря, после `)`.
- **Теги ставятся построчно в idle**, а не в обработчиках `insert-text`/`delete-range`: там
  итераторы ещё нужны самому GtkTextBuffer. Регулярка ссылки не пересекает перевод
  строки, поэтому перетэговываются только затронутые строки (грязная область — две метки
  с разной гравитацией). Idle стоит с приоритетом выше перерисовки — сырой текст не
  мелькает ни на кадр.
- **Любой текст из буфера берётся с `include_hidden_chars = true`** — сохранение, сравнение,
  копирование. GTK сериализует в буфер обмена только видимое, поэтому `copy-clipboard` и
  `cut-clipboard` перехвачены и кладут сырой текст; перетаскивание внутри выделения
  не начинается (клик в фазе захвата). Вставка — только текст, переводы строк
  нормализуются; в буфере всегда `\n`, стиль файла (CRLF/LF) восстанавливается при записи.
- **`set_text` необратим** (`begin_irreversible_action`): история undo не переживает загрузку
  файла — грабля Windows с затягиванием прежнего текста здесь не воспроизводится, а теги в
  историю не попадают вовсе, пропускать «шаги форматирования» не нужно. Составные правки —
  в `begin/end_user_action`.
- В режиме «как есть» теги снимаются явно, подсветка поиска остаётся.
- Попадание по ссылке — по прямоугольнику глифа (`iter_location`), а не по ближайшему
  символу (тот же урок, что на Android). Курсор-«рука» ставится **самому TextView**:
  дочернего виджета у текстовой области в GTK4 нет, курсор «text» стоит на нём же
  (поиск такого ребёнка не находил ничего, и «рука» не появлялась никогда). Сверяется
  на каждом движении мыши: GTK прячет указатель на время набора («none») и затем сам
  возвращает ему «text». Подсветка наведения снимается только с прежнего диапазона,
  не со всего буфера — иначе каждое пересечение ссылки раскладывало документ заново.
- Ссылка без якоря рисуется кружком в `snapshot` наследника TextView (`ndview.rs`).

Прочее, что отличается от Windows:

- Глобальные сочетания — `ShortcutController` в фазе захвата на содержимом окна: они
  срабатывают раньше привязок редактора и WebKit, но не внутри диалогов. Редакторные —
  на самом TextView, тоже в захвате: GTK отдаёт Ctrl+Y под redo, Alt+стрелки — под слова.
  Триггеры по keyval с латинским запасным вариантом — работают и в русской раскладке.
- git-операции блокирующие, идут через `gio::spawn_blocking`; окно живо, `git_busy` глушит
  слежение за диском. Слежение — crate `notify` (inotify), события из `.git` отбрасываются
  по первому сегменту пути. **События чтения (`EventKind::Access`) отбрасываются тоже**:
  `notify` подписан и на открытие файла, а перечитывание каталога открывает каждый файл —
  без фильтра оно запускало себя по кругу раз в полсекунды, и открытый просмотр (MD, SVG,
  YAML) каждый раз отбрасывало к началу. `FileSystemWatcher` на Windows чтения не видит
  (`NotifyFilter` — запись, имена, размер). По той же причине перечитывание не
  перерисовывает просмотр: изменившийся текст и так возвращает режим к тексту.
- `ScrolledWindow` оборачивает содержимое в `Viewport`: родитель списка — не окно прокрутки.
  Окно прокрутки с вертикальной политикой `Automatic` имеет минимальную высоту (полоса),
  поэтому у крошек стоит `External`. Правая колонка сама в окне прокрутки — иначе при шести
  карточках окно росло бы в высоту.
- Всплывающие подсказки — `Popover` без автоскрытия у кнопки; на Wayland это отдельная
  поверхность и в снимок окна (`NEURODOC_SNAPSHOT`) не попадает.
- Шрифты Inter и JetBrains Mono при запуске копируются в `~/.local/share/fonts/neurodoc-editor`
  (как Windows ставит их пользователю): их видят и Pango, и отдельный процесс WebKit.
- Id приложения `today.vab.NeurodocEditor` обязан совпадать с именем `.desktop`-файла:
  по нему GNOME на Wayland находит иконку окна. Приложение `NON_UNIQUE`: экземпляров может
  быть несколько, как на Windows, — иначе запуск на тестовом каталоге молча будил бы
  уже открытое окно.
- Списки панелей сортируются по кодам символов заголовка в нижнем регистре, как на Android;
  Windows сортирует с учётом локали (буква ё там идёт после е, здесь — после я).

## Подводные камни WinUI 3, уже проверенные на практике

- **`KeyboardAccelerator` с модификатором Alt срабатывает один раз**, затем XAML «залипает» в
  меню-режиме. Alt+←/→ поэтому обрабатываются в `RootGrid.PreviewKeyDown`.
- **RichEdit съедает часть сочетаний раньше глобальных акселераторов** (например, Ctrl+R —
  «выровнять вправо»). Такие сочетания перехватываются в `OnEditorPreviewKeyDown`.
- **`ScrollViewer` сам помечает событие колеса обработанным** — обычная XAML-подписка на
  `PointerWheelChanged` не вызывается вообще; нужен
  `AddHandler(..., handledEventsToo: true)`. Мало того, вертикальное колесо он не превращает
  в горизонтальную прокрутку сам — смещение задаём руками (`ScrollSidewaysOnWheel`; так
  прокручиваются панель путей, панель инструментов и строка кнопок форматов).
- **`ScrollViewer` в колонке `Auto` не прокручивается.** Колонка отдаёт ему всю желаемую ширину,
  полоса оказывается не уже содержимого, и обрезает её уже родитель. Прокручиваемую полосу
  кладём в колонку `*` (так сделана строка форматов: имя файла — `Auto` с `MaxWidth`,
  кнопки — `*`).
- Панель путей лежит **отдельной строкой `ContentArea` на всю ширину**, а не внутри колонки
  редактора: иначе появление путей опускало карточку редактора относительно правой панели.
- **`RowSpacing` у `Grid` считается и для строк со свёрнутым содержимым.** В правой панели первая
  строка — скрытая карточка поиска, и из-за `RowSpacing` колонка начиналась на 8 пикселей ниже
  редактора. Поэтому промежутки между карточками заданы их собственными `Margin`: у свёрнутого
  элемента поля не считаются, и верх колонок совпадает (проверено измерением по снимку).
- **`ProtectedCursor` работает только на самом hit-элементе** — курсор не наследуется от родителя, а
  у `RichEditBox` его text host принудительно ставит I-beam. Отсюда `ChipView`/`HandCanvas`.
- **Нативное выделение RichEdit не видно, пока фокус не в редакторе** — совпадения поиска
  подсвечиваются собственными прямоугольниками на оверлее.
- **`AppWindow.Resize` принимает физические пиксели** — размер окна масштабируется по
  `GetDpiForWindow`.
- **`KeyboardAcceleratorPlacementMode="Hidden"` на `RootGrid`** — иначе WinUI показывает плавающие
  подсказки вроде «Ctrl+S» в случайных местах окна.
- **bat-файлы держать в ASCII** (английский текст): cmd ломает парсинг UTF-8 с кириллицей даже после
  `chcp 65001`.
