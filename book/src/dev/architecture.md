# Архитектура

Три приложения — один домен и три разных набора средств для интерфейса. Ядро каталога,
git-слой и страницы просмотра повторяют друг друга по смыслу, а редактор на каждой
платформе устроен по-своему. Здесь — обзор, а подробности и проверенные грабли — в
[CLAUDE.md](https://github.com/vabuter/neurodoc/blob/main/CLAUDE.md).

| Слой | Windows | Linux | Android |
| --- | --- | --- | --- |
| Домен | `NeurodocCatalog.cs` | `domain/catalog.rs` | `data/NeurodocCatalog.kt` |
| Git | `GitService.cs` → git.exe | `domain/git.rs` → системный git | `data/GitService.kt` → JGit |
| Редактор | `RichEditBox` + оверлей | `GtkTextView` + теги | `BasicTextField` Compose |
| Просмотр | WebView2 | WebKitGTK | WebView |

## Каталог в памяти

`NeurodocCatalog` держит весь каталог в памяти: словарь «id → текст». Идентификатор —
`root`, UUID файла из `_content/` или путь вроде `contract/auth/start.yaml`. К нижнему
регистру приводятся только UUID: у пути регистр — часть имени.

**Чтение.** Сначала `root` и файлы `_content/` с именами-UUID, затем остальное дерево —
вручную, очередью папок: рекурсивное перечисление сначала обошло бы всё внутри `.git`.
Обход пропускает имена с точкой в начале, папку `_content` (по имени: точки в нём нет),
файлы больше 4 МБ и файлы с нулевым символом.

**Ссылки.** Регулярка одна на три платформы: `\[([^\]\n]*)\]\(([^()\s\\]+)\)`. Путь в ссылке
считается от файла, где она написана, поэтому цель разбирает
`TryResolveLink(sourceId, target)`. Веб-адреса, абсолютные пути и подъём выше корня
отвергаются, а `GetFilePath` на негодном id бросает исключение: прежняя молчаливая подмена
на `root` отправила бы запись не в тот файл. Источники ссылок — только `root` и
`_content/`: в YAML или Markdown запись `[текст](что-то)` встречается сама по себе. Правила
разбора — в главе [Ссылки](../format/links.md#куда-ведёт-цель).

**Кэш.** Разобранные ссылки кэшируются пофайлово: панели перестраиваются после каждого
автосохранения, и без кэша это пять прогонов регулярки по всему каталогу на правку. Запись
файла сбрасывает его ссылки в кэше, перечитывание — весь кэш. Любая новая операция над
словарём файлов обязана сбросить и кэш.

| Операция в C# | Что делает |
| --- | --- |
| `BuildGraph` | neurodoc-файл → файлы, на которые он ссылается |
| `GetBacklinks` | кто ссылается на файл; подстрокой не найти — один файл адресуют разными путями |
| `GetOrphanFiles` | neurodoc-файлы без входящих ссылок, кроме `root` |
| `GetBrokenLinks` | ссылки на несуществующие файлы и пути наружу каталога |
| `FindShortestPathsFromRoot` | хлебные крошки: обход в ширину, затем все пути минимальной длины (до 50) |
| `BuildReadingOrder` | обход в глубину от `root` по порядку ссылок в тексте, недостижимые — в хвост |
| `Search` | подстрока без учёта регистра по всем файлам, до 200 результатов |
| `RemoveLinksTo` | `[текст](цель)` → `текст`: якорь остаётся частью предложения |

Через файлы в собственных форматах обход дальше не идёт, и в порядок чтения они не входят.
Сами обходы описаны в главе [Граф знаний](../format/graph.md).

**Запись** — один метод `WriteFile`: UTF-8 без BOM и обновление памяти. Переводы строк не
меняются: Windows и Linux приводят текст редактора (RichEdit отдаёт CRLF, GTK — LF) к
стилю исходного файла.

## Слежение за диском

На Windows за каталогом следит `FileSystemWatcher`, на Linux — crate `notify` (inotify);
пачка событий гасится таймером на 500 мс, потом каталог перечитывается. На Android
слежения нет: каталог перечитывается после git-операций и миграции, а вручную — пунктом
меню «Обновить с диска».

Свою запись приложение отличает от чужой **по содержимому** (`MatchesDisk` /
`matches_disk`): событие пропускается, только если файл на диске совпадает с текстом в
памяти. Прежняя проверка «писали меньше секунды назад» глотала чужую правку сразу после
автосохранения. Сомнение решается в пользу перечитывания, двоичность файла — по нулевому
байту в первых 8 КБ. События из `.git` отбрасываются, на время своей git-операции слежение
молчит. На Linux отбрасываются и события чтения: перечитывание открывает каждый файл и
иначе запускало бы само себя. Как это выглядит для пользователя — в главе
[Навигация](../editor/navigation.md#правки-с-диска).

## Три порта одного домена

Linux- и Android-версии повторяют C#-домен файл в файл: то же разрешение ссылок, кэш,
кратчайшие пути, порядок чтения, обход дерева. Отличия вынужденные:

- **Позиции в тексте.** C# и Kotlin считают в единицах UTF-16, Rust — в байтах UTF-8, как
  `GtkTextBuffer`.
- **Регистр имён.** Словари регистронезависимые, но хранят написание с диска. На Linux
  файловая система различает регистр, поэтому запись идёт под уже известным написанием:
  иначе ссылка `readme.md` на `ReadMe.md` создала бы второй файл.
- **Сортировка списков.** Windows сортирует с учётом локали, Linux и Android — по кодам
  символов, и буква ё у них идёт после я.

## Редактор: три способа спрятать служебную часть ссылки

Снаружи редакторы одинаковы: от ссылки виден подчёркнутый якорь, ссылка без якоря —
кружок, «Как есть» показывает файл как на диске, автосохранение — через 700 мс после
последней правки. Внутри они разные.

- **Windows.** `RichEditBox` в режиме простого текста, поверх него — интерактивные «чипы»
  по прямоугольникам из `ITextRange.GetRect`. `]`, `(` и цель скрыты форматом `Hidden`, а
  `[` и `)` закрыты заплатками цвета фона: скрытые, они передали бы невидимость тексту,
  набранному вплотную. Координаты TOM не знают о прокрутке, поэтому редактор растёт на
  всю высоту текста внутри внешнего `ScrollViewer`. Форматирование попадает в стек
  отмены, и <kbd>Ctrl</kbd>+<kbd>Z</kbd> пропускает шаги, не менявшие текст.
- **Linux.** `GtkTextView` с тегами: `(цель)` скрыта тегом `invisible`, `[` и `]` красятся
  цветом фона. Страж в `mark-set` синхронно выводит каретку из скрытой части; теги
  расставляются построчно в простое главного цикла, раньше перерисовки. Сохранение и
  копирование берут текст вместе со скрытыми символами.
- **Android.** `VisualTransformation`: служебной части нет в показываемом тексте, а
  `CollapseOffsetMapping` пересчитывает позиции каретки и касаний. Касание проверяется по
  прямоугольникам глифов ссылки, а не по ближайшему символу.

## Просмотр форматов

Режимы — SVG, JSON, YAML, Bash, MD, AsciiDoc, HTML и nginx; при первом заходе в файл режим
выбирается по расширению. Страница собирается строкой HTML для WebView2, WebKitGTK или
WebView со всем нужным внутри: highlight.js, для MD и AsciiDoc — ещё marked или
Asciidoctor.js и встроенный шрифт (через `@font-face` с data-URI). Сеть не нужна.

Скрипты страниц (`ViewerLinkScript` для ссылок, `SvgZoomScript` для масштаба) побайтно
одинаковы на Windows и Linux: пользовательский скрипт WebKit подставляет
`window.chrome.webview.postMessage`, и страница думает, что она в WebView2. На Android
скрипт ссылок отличается последней строкой — вызовом моста `NeurodocHost.openLink`.
Дельта git выглядит одинаково на всех трёх платформах.

## Git-слой

`GitService.cs` и `git.rs` зовут системный git (на Linux — в фоновом потоке через
`gio::spawn_blocking`), `GitService.kt` работает со встроенным JGit.

- За каждым commit сразу идёт push; сообщение шаблонное: `yyyy-MM-dd HH:mm · <устройство>`.
- «Синхронизировать» — commit, pull с rebase и push. Если rebase не прошёл, он
  откатывается, и выбор за пользователем: конфликты не сливаются, резервных копий не
  делается. На десктопе отказ узнают по папке `.git/rebase-merge` или `.git/rebase-apply`.
- На десктопе git запускается с `-c core.quotepath=off` (иначе кириллица в именах приходит
  октальными последовательностями) и `GIT_TERMINAL_PROMPT=0` (без учётных данных — ошибка,
  а не зависание).
- При переключении веток правки прячутся в stash с меткой `neurodoc-auto:<ветка>`. Git
  приписывает к ней «On <ветка>: », поэтому запись ищут по хвосту сообщения.

Как это выглядит для пользователя — в главе [Совместная работа через git](../editor/git.md).
