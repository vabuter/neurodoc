# Проверки

Автотесты есть только у Linux-версии: тесты домена и git (`cargo test`) и самопроверка
интерфейса, которая сама проходит по экранам и снимает окно. Windows- и Android-версии
проверяют запуском. Правило для всех трёх одно: проверяют на копии `example/`, а
настоящие каталоги не трогают.

## Тесты Linux-версии

```bash
cd linux && cargo test
```

- `tests/domain.rs` работает во временных папках, большей частью — на копии `example/`:
  открытие каталога, ссылки по пути, согласованность обратных ссылок, путей и сирот, поиск,
  запись с сохранением написания имени, сверка с диском, снятие ссылок, битые ссылки и
  миграция, ссылка из буфера обмена и весь цикл git. Временные папки удаляются, `example/`
  остаётся как был. Тесты опираются на содержимое примера (конкретные файлы и слова),
  поэтому, меняя `example/`, проверьте и их.
- Цикл git (публикация, сохранение, ветки со stash, клонирование, получение, конфликт)
  идёт на локальном bare-репозитории по адресу `file://`, с собственной подписью автора
  через `GIT_CONFIG_GLOBAL` — без сети и ключей. Если git не установлен, тест пишет
  «git не найден — тест пропущен».
- Модульные тесты внутри `src/` проверяют разбор ссылок и пользовательского ввода,
  настройки, прогресс чтения, разбор вывода git, поиск и замену в тексте, выбор режима
  просмотра по расширению, форматирование JSON и сборку страниц просмотра.

Вместе с тестами прогоняют `cargo clippy`: правки Linux-версии в истории проекта
отмечены «cargo test и clippy чисто».

## Отдельный экземпляр для проверок

Linux-версия хранит настройки и список проектов в `$XDG_CONFIG_HOME/neurodoc-editor`
(обычно `~/.config/neurodoc-editor`). Если направить `XDG_CONFIG_HOME` во временную папку,
получится экземпляр со своими проектами и прогрессом чтения, а настоящие проекты
останутся нетронутыми. Уже открытое окно он не разбудит: приложение разрешает несколько
экземпляров.

Подготовка из корня репозитория — копия `example/`, превращённая в git-репозиторий (это
нужно шагам git в самопроверке), и настройки, где она единственный проект:

```bash
ND=$(mktemp -d)
mkdir -p "$ND/config/neurodoc-editor" "$ND/shots"
cp -r example "$ND/catalog"
git -C "$ND/catalog" init -q && git -C "$ND/catalog" add -A
git -C "$ND/catalog" -c user.name=test -c user.email=test@example.com commit -qm "Копия example"
cat > "$ND/config/neurodoc-editor/settings.json" <<EOF
{"currentProjectId": "test", "projects": [{"id": "test", "name": "Fikus", "path": "$ND/catalog"}]}
EOF
XDG_CONFIG_HOME="$ND/config" ./linux-run.sh --debug
```

Последняя строка собирает debug-версию и запускает её на копии. Без `settings.json`
приложение само открыло бы диалог «Проекты», и копию можно было бы добавить кнопкой
«Добавить». Журнал ошибок и резервные копии миграции эта переменная не переносит: они
лежат по `XDG_STATE_HOME` и `XDG_DATA_HOME`.

> [!WARNING]
> Путь в `XDG_CONFIG_HOME` должен быть абсолютным. Относительный приложение, как требует
> спецификация XDG, пропускает и берёт обычный `~/.config` — то есть ваши настоящие проекты.

## Самопроверка интерфейса

Нужны подготовленная выше копия и сборка приложения — подойдёт любая, ниже взята debug
(`./linux-build.sh --debug`):

```bash
XDG_CONFIG_HOME="$ND/config" NEURODOC_SMOKE="$ND/shots" ./linux/target/debug/neurodoc-editor 2> "$ND/smoke.log"
```

Приложение само открывает `root`, файл по первой ссылке, `contract/auth/start.yaml`,
`README.md` в просмотре и как текст, первую схему SVG из `_content/`, режим «Как есть»,
поиск по файлу и по проекту, «Битые ссылки», диалоги, всплывающую подсказку, историю и
дельту git, светлую тему — и после каждого шага кладёт снимок окна в папку:
`01-root.png`, `02-linked-file.png` и так далее. В конце окно закрывается само.

То, чего не видно на снимке, самопроверка проверяет сама и пишет в stderr:

| Строка | Что проверено |
| --- | --- |
| `smoke: курсор …` | над ссылкой курсор-«рука», вне ссылки — текстовый |
| `smoke: прокрутка …` | прокрутка не сбрасывается сама: у редактора — в покое, после перечитывания и после наведений на ссылки, у просмотра MD — в покое |
| `smoke: слежение …` | своё автосохранение не вызывает перечитывания; чужая правка сразу после него подхватывается — и в другом файле, и в том же; подхватывается и правка открытого файла с точкой в имени |

Провал выделен заглавными буквами — «НЕВЕРНО», «СБРОШЕНА», «ПОТЕРЯНА», — так что
достаточно поискать их в журнале:

```bash
grep -E 'НЕВЕРНО|СБРОШЕНА|ПОТЕРЯНА' "$ND/smoke.log"
```

Что нужно от каталога:

- шаги рассчитаны на пример: открывается `contract/auth/start.yaml`, по файлу ищется
  «fikus», по проекту — «авториз»;
- `root` и `README.md` длиннее окна — иначе прокрутка «не проверялась»;
- копия — git-репозиторий с коммитами, иначе карточка истории будет пустой;
- шаг слежения правит `root` и `README.md` копии и возвращает их как были, а временный
  `.smoke-watch.yml` создаёт и удаляет. Поэтому — только копия.

## Один снимок окна

```bash
XDG_CONFIG_HOME="$ND/config" NEURODOC_SNAPSHOT="$ND/window.png" ./linux/target/debug/neurodoc-editor
```

Снимок делается примерно через 2,5 секунды после показа окна. С
`NEURODOC_SNAPSHOT_QUIT=1` окно после снимка закрывается — удобно в скриптах. Всплывающие
подсказки на Wayland — отдельные поверхности и в снимок не попадают.

## Windows

Автотестов нет: изменения проверяют запуском приложения, а при правках интерфейса
снимают скриншот окна и смотрят на результат глазами. Отдельного экземпляра с
собственными настройками у Windows-версии нет: настройки всегда лежат в
`%APPDATA%\NeurodocEditor\settings.yaml`, необработанные исключения — в `error.log` рядом.
Поэтому копию `example/` во временной папке добавляют отдельным проектом в диалоге
«Проекты».

## Android

Автотестов нет — в `android/app/src/test` и `androidTest` лежат только заготовки мастера
Android Studio. Тестовый каталог кладут на телефон в `/sdcard/Develop/neurodoc_example`, а
проект переключают подменой `files/settings.json` через `adb shell run-as
today.vab.neurodoceditor` (так можно с debug-сборкой). После проверки файл возвращают
обратно: в нём список проектов пользователя и git-токены.

## git без сети

Все git-сценарии проверяются на локальном bare-репозитории — без сети и токенов:
`git init --bare`, а в приложении адрес вида `file:///путь/x.git` (на Windows —
`file:///C:/путь/x.git`, на Android — `file:///sdcard/…`). Если заливать bare-репозиторий
на телефон через `adb push`, теряются пустые папки `objects/` и `refs/` — их нужно
досоздать `mkdir`.
