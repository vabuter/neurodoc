# Каталог

Каталог neurodoc — обычная папка: файл `root`, папка `_content` с заметками и, если нужно,
папки с файлами в собственных форматах. Здесь — как называются файлы, как их опознают и
что при чтении каталога пропускается.

## root

Файл с именем `root` — строчными буквами, без расширения — лежит в корне каталога. С него
начинают читать, и он же корень графа знаний.

Открывая папку как проект, Neurodoc Editor досоздаёт недостающее: пустой `root`, папку
`_content` и `ReadMe.md` с описанием формата (если в корне нет файла `readme.md` в любом
регистре) — см. [Проекты и настройки](../editor/settings.md#проекты). Удалить `root` из редактора
нельзя — команда удаления для него недоступна.

## _content

Здесь лежат все остальные заметки. Имя файла — UUID в нижнем регистре, без расширения:

```text
_content/5c673c53-8ad9-49eb-9fb6-ffb3954848f0
```

- Папка плоская: вложенные папки внутри `_content` не читаются, файлы с именами не в виде
  UUID — тоже.
- Новые файлы редактор создаёт со случайным UUID — кнопками «Новая ссылка» и «Новый файл»
  (см. [Редактирование и ссылки](../editor/editing.md#новая-ссылка-и-новый-файл)).
- Подчёркивание в начале имени помечает папку служебной, но, в отличие от точки, не
  прячет её: каталог смотрят и файловым менеджером, и с телефона. Имя `content` оставлено
  свободным — под прикладную папку самого проекта.

## Файлы в собственных форматах

Всё остальное дерево — папки с YAML, SVG, JSON, конфигами, а также файлы в корне каталога
вроде `README.md`. На них ссылаются по пути; подробности — в главе
[Файлы в собственных форматах](own-formats.md).

## Идентификаторы

У каждого файла каталога есть идентификатор (id) — им файл называют в ссылках и в
программах:

| Файл | id |
| --- | --- |
| корневой | `root` |
| заметка из `_content` | UUID в нижнем регистре, без `_content/`: `5c673c53-8ad9-49eb-9fb6-ffb3954848f0` |
| файл в собственном формате | путь от корня каталога через `/`: `contract/auth/start.yaml` |

К нижнему регистру приводятся **только** UUID: у пути регистр — часть имени файла. Сам
редактор ищет файлы без учёта регистра — ссылка на `readme.md` найдёт `ReadMe.md` во всех
трёх версиях, — но программа, открывающая файл по пути напрямую, на Linux его не найдёт.
Пишите путь точно так, как он записан на диске.

## Заголовок

Заголовок заметки — её первая непустая строка. Пробелы по краям и ведущие символы `#`
отбрасываются, поэтому строка `# Подход к разработке` даёт заголовок «Подход к
разработке».

- Заголовок подставляют вместо пустого якоря ссылки. Редактор показывает его в панелях и
  в путях от `root`, а на Windows и Linux — ещё и в подсказке при наведении на ссылку.
  Длинный заголовок обрезается многоточием.
- У пустого файла заголовка нет — панели показывают вместо него начало UUID.
- У файла в собственном формате заголовок — имя файла (`start.yaml`): первая строка там
  служебная — комментарий или ключ.

## Кодировка и переводы строк

- Все файлы — в UTF-8 без BOM. Это часть формата, а не пожелание; редактор пишет файлы
  только так.
- Переводов строк формат не задаёт, в каталогах обычно LF. Windows- и Linux-версии
  редактора стиль файла при записи не меняют: файл с CRLF так и останется с CRLF.

> [!WARNING]
> Если каталог лежит в git, закрепите LF в `.gitattributes` строкой `* text=auto eol=lf`.
> Иначе Git for Windows, у которого преобразование включено по умолчанию, при клоне
> развернёт файлы в CRLF — и редактор, сохраняя стиль файла, будет записывать CRLF и дальше.

## Что при чтении пропускается

Редактор держит весь каталог в памяти как таблицу «id → текст». В неё не попадают:

- папки и файлы, чьё имя начинается с точки: `.git`, `.gitlab-ci.yml`;
- в `_content` — вложенные папки и файлы с именами не в виде UUID;
- среди файлов в собственных форматах — файлы больше 4 МБ и двоичные (с нулевым символом
  внутри): каталог — не хранилище двоичных данных.

В поиск по проекту такие файлы не попадают. Но ссылка на существующий файл из этого списка
битой не считается: наличие цели редактор проверяет и на диске, а открытый по ссылке файл
читает с диска напрямую.
